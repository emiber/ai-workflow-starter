# finish-epic

Close out the target epic (its number on GitHub or key on Jira — provided as the argument, or stated by the user) by opening its integration PR, following the contract in `workflow/epics.md`. This is the canonical playbook: Codex runs it directly and the Claude Code `/finish-epic` command delegates to it.

1. Read `workflow/rules.md`, `workflow/principles.md`, `workflow/epics.md`, and `workflow/issue-tracker.md`.
2. Run the preflight from `workflow/epics.md` (`/finish-epic` section). It's read-only — if one fails, stop and report the fix. It confirms the target really is an epic and finds its integration branch by number: the one branch matching the `epic/<n>-` prefix, locally or on `origin`, never a slug re-derived from the title. None, more than one, or a failed lookup stops the flow. Every later step uses the resolved branch.
3. Fetch the epic and its children, and use that list only once the listing command has succeeded — with the REST fallback, every page (see `workflow/epics.md` step 1 and `workflow/issue-tracker.md`). If the listing fails, even after printing some children, discard its output and stop: report the epic and the error, before any sync, push, `Closes` line, or PR. Then list the PRs into the resolved epic branch (`gh pr list --base <epic branch> --state all`; see `workflow/epics.md` step 2) and check every child on the list. A child's PRs are those whose head branch matches `*/<childN>-*`, and the child is done when one of them is **merged** — the child *issue* may still be open (that's the recommended default). If any child is missing (no PR into the epic branch), still open, or closed without merging, or the lookup fails, **stop and report them and do not open the integration PR** — there is no "proceed anyway".
4. Sync the resolved epic branch with the latest `main`, as in `workflow/epics.md` step 3: fetch and check it out; stop and report if the local epic branch has commits that aren't on `origin`, ahead or diverged (the ancestry check); otherwise fast-forward it from `origin`, then merge `main` into it (`git merge origin/main`), resolve conflicts, and commit the merge — don't push yet. When the merge stops on conflicts, record the conflicted files (`git diff --name-only --diff-filter=U`) before resolving or staging anything. If the merge made a commit (not "Already up to date", not a fast-forward), record its SHA right after committing it as `<merge>` (`git rev-parse HEAD`). Never reset, rebase, or force-push the epic branch.
5. Validate the final revision before any push, as in `workflow/epics.md` step 4 — in this run, even when the merge was conflict-free or already up to date; a child's verification, an earlier run, or CI never counts. With a clean tree, note the HEAD SHA. Run the complete quality gate: the lint and test-with-coverage commands from the Quality gate section of `docs/ARCHITECTURE.md` (if missing, found in the project's own scripts, configuration and CI) plus the other checks CI runs, with total coverage at or above the threshold (default 85%) and each new or changed source file below it listed with the reason. Then a focused, read-only integration review (`workflow/pr-review.md`, local diff mode, epic integration) of the conflict resolutions, the integration fixes and what `main` brought in, against the acceptance criteria of the epic and the children they affect — by a fresh agent, or inline (say which). Give it the base `origin/main` and the merge context: `git diff origin/epic/<n>-<slug> HEAD` and, if step 4 recorded a merge commit `<merge>`, its SHA and the conflicted files recorded there, whose resolutions it reads in full (`git show --remerge-diff <merge>` also shows them, Git 2.36+; `git show --cc` misses one-sided resolutions). Any fix or other change makes a new candidate: commit it and run the gate and the review again for the new SHA. A failed, unrunnable or below-threshold gate, unresolved conflicts, or a remaining review blocker → stop and report before any push or PR. Never weaken tests, lower the threshold, skip hooks, or call a failure `n/a`; a pass never waives step 4's ancestry check.
6. Push the resolved epic branch — only if the tree is clean and HEAD is still the validated SHA; a rejected push → stop and report, no PR, never force — then open the PR from it to `main` with `gh pr create --base main`. Body aggregates `Closes #<n>` plus one `Closes #<child>` per child on step 3's list, each exactly once (GitHub), so merging closes the whole tree; on Jira, put the Epic key in the title and list child keys. It also has a **Verification** section naming the validated SHA, with all six gates (lint, tests, coverage, self-review, security, docs) as in `workflow/epics.md` step 5, and an **Out of scope / follow-ups** section; links to the children's PRs never replace it.
7. **Don't merge.** Leave the PR open for human review and return its link.

If any step fails, stop and report. Don't improvise destructive workarounds or use `--force`.
